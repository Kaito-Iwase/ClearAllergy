対象は `clearallergy-docs-ja-main`、base `cd502b2404f518975dc4243ab6c41a702e7aa226`。原文は同worktreeの `docs/research/originals/20261015-ja-readability/` に保存した2ファイル。以下は編集上の照合であり、危険の発生確率・実地効果・現在の修正状態の再調査ではない。

## 専門用語の扱い

| 用語・原稿の表現 | 派生本文での説明 | 照合の根拠 |
| --- | --- | --- |
| STPA / STPA-inspired | 初出で「システム全体の動きや人の操作から、事故につながる状況を洗い出す安全分析手法」と括弧説明。考え方を参考にした範囲と全手順の未実施を分ける | [MITの解説](https://psas.scripts.mit.edu/home/books-and-handbooks/)、[Handbook2018](https://psas.scripts.mit.edu/home/get_file.php?name=STPA_Handbook.pdf) p4。原稿の出典X10を維持 |
| Loss / Hazard | 避けたい被害・不利益と、周囲の悪条件と重なると被害に至り得るシステムの状況を区別する | Handbook p16–18の定義。一般的な「危険」と完全STPAの形式分類を同一視しない |
| prototype | 「機能や使い方を確かめるための試作品」と初出で補足 | 当時の架空データという使用境界を維持 |
| FREE / enum / master | 「原材料に含まないことを表す値」「保存できる状態の候補を定めた型」「対象品目の共通定義」 | 元原稿H01/H02と根拠一覧。FREEを厨房の交差接触までの確認へ広げない |
| API / HTTP 500 / 再POST | 処理を呼び出す窓口、サーバー側の処理失敗を示す応答、作成要求の再送と説明 | H02/H04の文脈。保存確定と画面が知る結果を区別 |
| updatedAt | 一般的なデータ更新日時と括弧説明 | 食品内容の確認日時と同一視しないH05を保持 |
| ISR | 保存済みのページを再生成しながら配信する仕組みと補足 | 当時の配信方式の検討対象。現行アプリも同方式だとは書かない |
| STORE_HANDLED | 店舗内の取扱い情報から表示する補足と括弧説明 | 厨房確認済みという意味への取り違えをH07で維持 |
| screen reader / Blob / orphan / proxy | 音声などの支援技術、画像保存先、参照されず残る画像、アクセス先に応じてページを保護する処理へ展開 | 元原稿H07/H08/H10の操作・対象を保持 |

## 原稿の情報から本文への対応

| 原稿にある情報 | 派生本文の位置と保持のしかた |
| --- | --- |
| X10を参考、多職種検討会・厨房観察・完全STPAなし | 冒頭「分析の方法」で全て明記。用語確認の2026-10-15と研究の2026-09-28を区別 |
| 重大性を扱うが発生確率・定量順位を算出しない | 同節の独立段落。未測定を解決済みへ変更しない |
| 身体被害は想定用途外、将来実利用・誤転用を含む | 同節の使用境界。現実の事故実績に読み替えない |
| L01–L04 | 4項目を分け、身体被害/機会損失・過度の回避/情報・権限侵害/原因特定・修正・復旧不能による長期化を保持 |
| H01: string cast→FREE fallback、EX01、将来enum/import不整合 | 型と判定の説明、合成入力を使う局所実験、将来の型変更・取込の食い違いを保持 |
| H02: API/DB迂回、master変更、flagだけ参照 | 検査の迂回・品目定義の変更・公開値だけで判断する条件を文章化 |
| H03: resource ID差替え、guard/write時間差、email前提 | 対象IDの差替え、サーバーの権限確認から書込までの所有関係変化、メールだけを根拠にする条件を展開 |
| H04: 2tab全status更新、commit後500、再POST | 担当者が先に訂正→古いタブで全品目保存、DB保存確定→後処理エラー→未保存案内→作成再送という順序へ。2ケースを分ける |
| H05: recipe/仕入変更未通知、一般updatedAt更新、review証跡なし | 変更未報告、単なる更新と食品確認の違い、確認記録がない場合を全て保持 |
| H06: ISR・DB直接修正・open tab・別query時点差 | 4経路を残し、サーバー修正と既存画面への到達の違いを説明。過去の方式と明示 |
| H07: 緑=安全、STORE_HANDLED=厨房確認、29以外、代理人設定違い、screen reader | 5観点を保持。「29」は研究時点の対象と限定 |
| H08: 下書き/削除画像、public Blob独立、orphan | メニューの公開・削除と画像そのもののアクセスを分け、参照のない残存画像も保持 |
| H09: best effort audit、通知/restore不明、provider結果不明 | 監査保存の失敗時方針、調査での通知・復旧未確認、外部サービスの結果不明を保持。未確認と不存在を区別 |
| H10: migration未適用、秘密値/client、旧package、proxy条件 | DB構造変更の未適用、ブラウザへの秘密露出、古い依存、保護条件という4点を保持 |
| 各HのL/SC/要件ID | 全10行を原表から抽出して新節と照合。一致。全体38管理識別子の集合も一致。出典X10/EX01の2識別子も保持 |
| Unsafe control action 4種類 | 操作しない/不適切に行う/順序・時刻が悪い/長過ぎる・短過ぎるを元の例とともに保持 |
| 正しいdata＋誤UI、人同士の伝達 | 4種類の後に独立段落として保持 |
| Counter scenarios 4条件 | H01通常経路のAPI/Zod/DB列挙型、H02共通判定/遅延トリガー、1人でも2タブ・頻度未測定、試作品と身体被害の距離を保持 |
| 危険候補を本番事故にしない | 冒頭・各Hの前・反証節末尾で時点と観察の境界を明記 |
