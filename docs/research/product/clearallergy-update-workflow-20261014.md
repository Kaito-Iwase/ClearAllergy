# ClearAllergy 更新運用の検討

変更を検知してから確認・公開・訂正まで。小規模店で継続できることと、誤った安心を与えないことを両立する設計案。


# 更新フローと運用・非機能要件

# ClearAllergy：情報を更新し続ける業務フロー案

調査・再確認日：2026年10月14日（UTC）  
対象：アレルギー対応が進んでいない店舗。個人店を中心に、チェーンの店舗・本部も含む。  
範囲：業務・要件の提案。実装、店舗の実査、医学的評価、法適合判定は行っていない。

## 1. 結論

更新の中心は「入力画面」ではなく、変更に気づき、影響する情報を保留し、実際の食材・調理と照合して再公開する一連の仕事である。

最初に設計すべき点は次の三つ。

1. **いつから現物が変わるか**。来週の変更予定なら現行情報を維持できる場合がある。一方、既に代替材料を使ったなら、以前の情報を現行として維持してはいけない。
2. **誰が不確実な表示を止められるか**。訂正の承認待ちで誤情報を残さない。保留・停止と、内容を確定して再公開する権限は分けて考える。
3. **何を確認すれば再公開できるか**。「確認済み」のボタンだけでなく、対象商品・レシピ・対象期間・調理条件と根拠が対応することを確かめる。

一人営業でも自己確認による運用は候補になる。ただし、二回押すことを独立した二人確認と同等には扱わない。根拠不明・矛盾・影響範囲不明を確認済みに変える抜け道を設けない。

## 2. 確認できた事実と、提案の区別

### 確認できた事実

- 消費者庁は外食・中食の経営者・従業員と消費者向けの教材を公開している。2026年10月14日に確認した掲載ページでは、事業者向け・消費者向けパンフレットはいずれも令和8年7月版。掲載内容には情報提供、意図しない混入、誤食事例、緊急時対応などが含まれる。[S1]
- 厚生労働省サイト掲載の小規模飲食店向け手引書資料には、アレルゲン情報について最新性・正確性、曖昧な回答の回避、メニュー情報の把握を勧める記述がある。ただし閲覧した資料は2023年時点で、改訂資料を含むため、現行の対象品目数や法的義務を判断する根拠には使っていない。[S2]
- OWASPは、最小権限、既定拒否、要求ごとの権限確認、サーバー側でのアクセス制御を推奨している。[S3]
- OWASPは、時点・主体・対象・結果などを追えるログ、ログの保護、機微情報や認証情報の不用意な記録の回避を示している。[S4]

### 以下のフローは設計提案

状態名、承認人数、対象資料、保留範囲、入力項目、運用の頻度は、ClearAllergy向けに組み立てた候補であり、公的資料がこのワークフローを指定しているわけではない。全項目を全店舗に一律必須とする提案でもない。

### 未検証

実店舗での所要時間、取りこぼし率、仕入先の資料提供能力、繁忙時の実行可能性、店員・客の表示理解、月額の支払意思額は未検証。アプリに変更が入力されない場合に自動で気づけるとは限らない。

## 3. 情報と状態を分ける

### 内容の状態

- 原材料として使用を確認した
- 確認したレシピ・資料の範囲で、原材料として不使用
- 未確認・不明・資料の矛盾あり

交差接触に関する設備・器具・保管・調理上の情報は別項目とする。材料の不使用を「食べても安全」へ変換しない。対象にしていないアレルゲンを不使用扱いにしない。

### 公開・作業の状態

- 下書き：客側には出ない
- 確認中：担当者が資料・現物・影響を確認中
- 公開中：定義した確認が完了した版を提供
- 要再確認・情報提供保留：旧版を現行の確定情報として出さない
- 終了・撤回：対象期間終了、商品終了、誤情報の撤回等

「未確認という事実を公開すること」と「未確認の内容を確定情報として公開すること」は区別する。客側に店舗名・メニュー名と『現在この項目は確認できていません』を出す運用は可能。全ページを消して理由不明にする必要はない。

公開データには、確認対象、確認日、適用店舗、適用期間・版を対応させる。内部の担当者名や取引先資料をそのまま一般公開する必要はない。

## 4. 共通の更新フロー

| 段階 | 実施すること | 完了の確認 |
|---|---|---|
| 1. 変更を検知 | 納品、買い足し、レシピ変更、器具・作業変更、顧客指摘等を受付。『何が変わった／いつから使う／既に使ったか』を先に記録 | 変更対象と適用時点が分かる。不明なら不明として保留範囲を広げる |
| 2. 責任者を決める | 現場の確認担当と公開責任者に割り当てる。一人営業は兼任。本部資料の変更と店舗の実使用確認を区別 | 担当不在時の代替者または情報保留手順がある |
| 3. 現行表示を保護 | 既に変更・誤りの疑いがある場合は関係項目を要再確認にする。将来変更は適用前の下書きで準備 | 既に変わった内容について旧版が現行として表示されない |
| 4. 根拠を照合 | 現物の商品名・メーカー・必要な識別情報と、包装表示・仕様書・仕入先回答・レシピ等を照合。調理条件は現場確認 | 根拠が別商品・旧版・別店舗を指していない。矛盾が未解決なら確定しない |
| 5. 影響を確認 | 共通ソース、下味、付け合わせ、トッピング、セット品、店舗別変更をたどる | 自動で出した関連候補を人が確認。登録漏れが疑われる場合は候補だけで完了しない |
| 6. 公開前確認 | 差分、対象店舗・期間、現物との一致、未確認の残り、交差接触情報への影響を確認 | 承認後に対象内容が変われば承認をやり直す。客側表示をプレビュー |
| 7. 再公開・現場連絡 | 適用開始と合わせて版を切り替える。接客担当・厨房への共有、紙資料の差替えを行う | 保存成功だけでなく、客側で新しい状態が取得できることを確認 |
| 8. 履歴・振り返り | 変更理由、根拠、担当、適用時点、公開・保留時点、対象範囲を残す | 誤りがあった期間を後から追える。定期確認で同じ漏れを減らす |

責任者への通知を送っただけでは更新完了にしない。確認・公開・現場への反映を分けて進捗が分かるようにする。

## 5. 場面別の扱い

### A. 仕入先・メーカー・仕様の変更

- トリガー：発注変更、納品商品の違い、包装表示変更、仕入先からの改訂連絡。同じ商品名でも変更があり得る前提で扱う。
- 責任者：発注・納品を確認する人が起票し、レシピを把握する人が影響確認。チェーンは本部の商品情報担当と各店舗の実使用担当。
- 根拠：新旧の商品を特定できる包装・仕様情報、改訂連絡、現物確認。バーコードや商品名だけで内容不変と断定しない。
- 影響範囲：その材料を使うソース・仕込み・全メニュー・セット品・利用店舗。
- 確認中の公開状態：新材料使用前は旧材料の情報を適用範囲内で継続可。新材料を使い始めた後は関係情報を保留。
- 再公開：実際の切替を確認して版を切り替える。旧在庫と新在庫が並行するなら、提供版を区別するか、区別できない範囲を未確定として扱う。
- 履歴：変更通知受領日、実使用開始、旧在庫終了、対象商品・店舗・資料版。

### B. 欠品時の代替材料・当日の買い足し

- トリガー：予定と違う材料を購入・開封・使用する判断。
- 責任者：代替を決めた人がその場で保留。確認できる責任者が資料とメニューを照合。
- 根拠：代替商品の包装と当日のレシピ。『似た商品』『いつも大丈夫』は確認根拠にしない。
- 影響範囲：当日の該当仕込み・メニュー・提供時間。混在や開始時点不明なら範囲を広げる。
- 確認中：関係情報を保留し、接客担当にも伝える。アプリ上の保留は食品提供そのものの可否判断を代行しない。
- 再公開：当日の代替版を確認。代替終了時も通常版へ自動で戻さず、実際に元の材料へ戻ったことを確認。
- 履歴：代替理由、使用期間、対象仕込み、確認者。原則として長文の説明より選択肢と必要な証拠を優先。

### C. 日替わり・季節・都度変わるメニュー

- トリガー：その日のメニュー決定、仕込み変更。
- 責任者：当日の調理責任者。
- 根拠：共通ベースと当日の追加・除外・ソース・付け合わせ。
- 影響範囲：日付・営業時間・対象メニューを明確化。
- 確認中：『本日分は未確認』を表示。昨日の内容を本日の確認済みに引き継がない。
- 再公開：差分確認で済む部分と、元資料の再確認が必要な部分を分ける。終了時点を定義する。
- 履歴：適用日、ベース版、当日の差分。毎回すべてを入力し直す設計は避ける。

### D. 担当不在・一人営業・引継ぎ失敗

- トリガー：担当者休暇、離職、急な変更に対応できる人がいない。
- 責任者：事前に指定した代理者。代理者が確認できなければ保留を維持。
- 根拠：保管された資料・レシピ・更新履歴。担当者の記憶だけに依存しない。
- 影響範囲：変更された部分を中心に確認。担当がいないだけで有効な全情報を必ず停止するものではない。
- 確認中：根拠を確認できない質問には不明と回答。無権限者が公開を確定しない。
- 再公開：代理者または戻った責任者が確認。引継ぎ完了を記録。
- 履歴：担当変更、確認不能の理由、残った作業。退職者の権限停止は別途管理する。[S3]

### E. 原材料不明・複合原材料の内訳不明・資料の矛盾

- トリガー：包装欠落、仕様書なし、仕入先回答と現物が違う、ソース等の内訳不足。
- 責任者：仕入先へ確認できる人と公開責任者。
- 根拠：現物と一致する資料または特定可能な仕入先回答。OCR・AIの推定は下書き補助に限る案。
- 影響範囲：不明な材料から関係メニューへ伝播。分からない範囲を過小評価しない。
- 確認中：不明を明示し、不使用へ変換しない。別の材料で使用が確認できたアレルゲンの情報まで消す必要はないが、全体確認済みと誤認させない。
- 再公開：不明点が解消した項目だけ確定できる。資料が得られなければ未確認状態を継続する。
- 履歴：問い合わせ先・回答日・未解決点。仕入先の内部資料を公開しない。

### F. 誤情報の申告・誤公開・健康被害の申告

- トリガー：客・店員・仕入先からの指摘、チェックでの発見。
- 責任者：受付者は即時に担当へ引継ぎ。指定された現場担当者が関連表示を保留できる。内容確定は公開責任者。
- 根拠：指摘内容、当時の公開版、使用材料・提供期間など。公開情報の誤りに関する記録と、個人の健康情報は分け、後者の収集を最小限にする。[S4]
- 影響範囲：該当メニュー・関連材料・店舗・提供期間・紙資料。範囲が分からなければ関連候補全体を保留。
- 確認中：疑いのある表示を停止し、確認中と明示。公開停止は訂正内容の完成を待たない。
- 再公開：原因・正しい情報・対象範囲を確認し、訂正として新しい版を公開。必要な関係者への連絡と表示差替えを確認する。
- 履歴：発見、保留、旧版の公開期間、訂正内容、再公開、再発防止。医療対応・事故時連絡は店舗の別手順に接続し、アプリ内で医学的判断をしない。

### G. オフライン・古い表示・印刷物

- トリガー：通信失敗、更新反映失敗、端末の保存済み表示、紙の旧版。
- 責任者：システム側は障害検知と状態表示、店舗側は現場での情報提供を管理。
- 根拠：最終取得時点、確認時点、公開版、通信状態を区別。
- 影響範囲：接続中の端末、断線端末、印刷物、画面保存は更新可能性が異なる。
- 確認中：通信失敗をアレルゲンなしにしない。初期版ではオフライン中は確定情報の提供を停止する案を優先検討。保存版を提供するなら、保存時点と最新性未確認を目立たせる。
- 再公開：再接続時に現行版と撤回状態を照合。古い下書きで新しい訂正を上書きしない。紙は版・印刷日を表示し、担当者が差替え。
- 履歴：障害・更新反映の状況、紙差替え確認。断線した客の端末やスクリーンショットを即時に撤回できるとは約束しない。

### H. バックアップ復旧・誤操作の巻戻し

- トリガー：障害、データ破損、誤削除、復旧作業。
- 責任者：運営側復旧担当と店舗の公開責任者。
- 根拠：バックアップ時点と、その後の変更・撤回・公開履歴。
- 影響範囲：復旧対象店舗、材料、メニュー、権限、公開状態。
- 確認中：復旧前の古い版をそのまま現行公開しない。訂正・撤回を再適用するか、再確認まで保留。
- 再公開：サンプル確認だけでなく、復旧で失われ得る変更範囲を特定して照合。確認不能部分を残して一括公開しない。
- 履歴：復旧対象時点、失われた可能性のある更新、再適用した訂正、承認と公開時点。

## 6. 一人営業とチェーンへの適用

### 一人営業

自己入力・自己確認を許容する案。納品・開封時に資料を残し、変更部分と客側表示を別の確認画面で照合する。二人目がいないために保留操作まで止めない。確認できない間は未確認を維持できることが重要。

一方、自己確認は独立レビューではない。理解不足・見落としが減るかは試用で検証する。確認時間を確保できず入力も継続できないなら、対象メニューを縮小し、未確認を明示する運用へ戻す。操作を簡単にするために根拠確認を削らない。

### チェーン・複数店舗

本部が共通材料・レシピを更新し、店舗が実際の切替日・旧在庫・代替・現場条件を確認する。全店一括更新でも店ごとの実態が同じとは限らない。本部の承認だけで全店の実使用を確認済みにしない。共通データと店舗固有差分の上書きルールが必要。

### 二人承認を検討する場面

多数店舗へ一括反映する変更、複雑な組合せ、誤情報発生後の訂正、担当者が内容を判断できない場合などは、別担当の確認に価値がある。ただし法律上の一律必須とは主張しない。二人いても同じ誤資料を見ているだけなら十分ではない。根拠不足や資料矛盾は人数では解消しない。

## 7. 入力負担を抑える案

- まず『変更あり／なし／分からない』『何をいつから使うか』を入口にし、変更部分だけを確認。
- 店舗・時刻・担当・公開版・変更差分は可能な限り自動記録。毎回手入力させない。
- 材料と関連メニューを再利用するが、関係図を最初から完全登録する重い作業が成立するか検証する。初期段階は対象メニューを絞る。
- 根拠は写真、資料参照、所在、版などから店舗が扱える方式を選ぶ。全食材の全包装を毎回アップロード必須にはしない。ただし対象の同一性・最新性を後から確認できる水準は必要。
- OCR・AI候補は原資料と並べて確認し、自動確定しない。誤読した否定表現や材料名を受入試験に入れる。
- 『変更なし』の一括確認は、何を見て確認するかを限定してから採用。ログイン・画面閲覧だけで最終確認日を更新しない。
- 通知は担当者に未完了分をまとめる。ただし、使用中の誤情報の保留が通知を読むまで遅れる設計にしない。

## 8. 検証計画と受入試験候補

実食で安全性を試すのではなく、架空の変更・資料・メニューを使った業務シミュレーションから始める。

| テスト | 観察・判定すること |
|---|---|
| 共通ソースのメーカー変更 | 関連するメニューを漏れなく特定できるか。登録外の利用も現場確認で拾えるか |
| 営業中の急な代替 | 使用開始前後を区別し、旧版の確定表示を止められるか |
| 日替わりを前日から複製 | 確認日・適用日・変更部分が未確認として引き継がれるか |
| 仕入先の回答と包装が矛盾 | 不使用に確定せず、保留と質問に進めるか |
| 責任者不在 | 無権限公開をせず、代理者または保留で処理できるか |
| 一人で入力・確認 | 原資料と画面の不一致、対象メニューの誤選択に気づけるか |
| 承認後の追加編集 | 以前の承認で変更後の版が公開されないか |
| 公開後の誤り発見 | 訂正完成を待たず保留にでき、旧版の期間と影響を追えるか |
| 圏外・古いキャッシュ | 最新でないことが理解できるか。再接続で撤回済み表示が残らないか |
| 復旧で訂正前に戻る | 旧版が無条件で再公開されず、訂正・撤回を照合できるか |
| 他店舗IDへの差替え | 非公開情報取得、編集、承認、根拠ファイル取得を拒否するか [S3] |

測る指標：初期登録と1変更の所要時間、確認に必要な資料が揃う割合、影響範囲の取りこぼし、保留までの時間、再公開までの時間、未処理の滞留、説明の誤解、店側の問い合わせ工数。平均だけでなく繁忙時・担当不在時も観察する。

受入試験では『未確認が不使用へ変換された』『権限外公開ができた』などの重大な挙動は不合格とする案。実験で事故が起きなかったことを、食品の安全性や医療安全の証明にしない。

## 9. 検索・絞り込みにも確認状態を反映する

【設計提案】一覧・検索・個人設定の除外条件も、詳細画面と同じ公開版・対象品目・確認状態を参照する。「原材料として不使用」で絞り込む場合、未確認・確認対象外・保留・期限切れを不使用へ変換して結果に含めない。含有が見つからなかったことだけを不使用の根拠にしない。特に推奨表示の品目、表示制度の対象外の食物、確認範囲外の成分は、ラベルに書かれていないことから不使用と確定しない。経過措置中の表示も同様に原資料・メーカー等で確認する。変更や公開停止が起きた場合は、検索結果の表示、検索索引、接続中の端末やCDNのキャッシュにも伝播させる。公開版と撤回状態の照合に失敗した場合、以前の確定表示へ戻さず確認できない状態を示す。鮮度を確認できない保存済み検索結果には、その制約を表示する。

不使用という表示は、交差接触がないことや本人が安全に食べられることを保証しない。検索結果からも混入情報・対象範囲・確認日を確認できる導線を設け、店頭確認につなげる。

【追加受入試験】材料変更で保留になったメニューが、不使用フィルター・お気に入り・直URL・古い検索結果で確認済みのまま残らないかを試験する。

## 10. 次に合意する条件

1. **最初の対象と確認範囲**：どの成熟度の店舗、何メニュー、どの情報を扱い、何を未確認として残せるか。
2. **現場の責任と停止条件**：誰が納品・変更に気づき、保留・確認・再公開を行うか。担当不在、根拠不明、混在在庫時にどうするか。
3. **継続できる負担と品質目標**：月額・初期作業・更新時間・資料保管、表示反映時間、停止・復旧目標、確認頻度。数値は店舗試用後に決める。
