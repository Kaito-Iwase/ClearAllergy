個人飲食店の導入・更新負担、誤表示等の防止策、情報の継続管理の3原稿に、同日の独立レビューの訂正を統合した追補です。一次資料、ベンダー説明、研究の効果検証、調査者の推論を区別し、現在のClearAllergyの製品仕様や安全保証へ昇格させません。アプリの実装・移動、店舗への連絡、契約・問い合わせ、本番操作は行っていません。

## 調査で支持される範囲

1. 情報源、何を確認したか、料理との対応、変更、未確認を追えることには検討価値があります。これが低負担の有料サービスとして成立することは、まだ証明されていません。
2. 最新の供給元データと実際に使う材料は一致しない場合があります。通知や公開更新だけで完了とせず、現物との対応が取れないときの扱いを確認する必要があります。
3. 原材料の使用情報、交差接触、店舗の対応可能範囲、患者本人の摂食判断は異なります。情報確認を安全保証や除去対応完了として表示しません。
4. 対応未整備の小規模飲食店について、初期工数、継続工数、情報入手率、支払意思、放置・離脱率の実測が欠けています。初期と継続の負担の大小も未測定です。
5. 注文・調理・配膳は周辺リスクとして認識しますが、今回の情報管理の調査から現在の製品範囲へ追加しません。情報一覧が正しくても、当該注文への伝達や現物の混入は別の経路で失敗し得ます。

## 独立レビューの訂正を統合した境界

| 論点 | 統合後の扱い |
| --- | --- |
| 注文ID・厨房受領・配膳照合 | 詳細は誤表示対策文書の周辺業務の参考へ集約。現在の候補仕様・必須測定から除外。将来の別検討では既存POS・紙、ピーク時負担、健康情報の取扱いを比較する |
| 初期と継続の負担 | 両方に作業があることと、どちらが大きいかを分ける。対象店の初期台帳がない場合の障壁も未測定 |
| 未使用の確認と未確認 | 原材料の使用有無を根拠と対象範囲付きで確認した状態と、確認できていない状態を分離。工程の交差接触と分け、具体的ラベルの理解度は未検証 |
| 最小性と担当者 | 管理すべき論点と毎回の手入力を分ける。代理のない一人営業も対象。紙・表計算、少数の料理で比較し、全品ロット追跡、多人数承認、常時通知、POS連携を必須化しない |
| 人の確認 | 承認結果を真実の基準にしない。既知の変更・欠落を埋め込む模擬ケースに独立した正解／未確定の基準を用意し、確認完了率と誤った否定表示率を分ける。専門家の対象・根拠も記録する |

原稿の古い問題表現を残して末尾だけで訂正する構成にはしていません。運用候補の最小性・低負担・継続利用・事故低減を実証した記録ではなく、製品やDBの状態追加も行っていません。

## 次に検証する順序の提案

以下は情報収集から導いた順序であり、店舗協力の募集・連絡、実装、データ取得契約を進める指示ではありません。最適な順序や最小構成を実証した結果でもありません。

### 1. 対象と現状の実作業を定義する

「個人経営」「小規模」「独立店」「未対応」「情報が未整備」を分けます。口頭対応はあるが資料がない店と、対応自体を受けていない店では仕事が異なります。協力的な先進店だけに寄らず、導入しない理由も収集する調査案です。3〜5店は探索には使えても、市場比率・価格の代表値を推定できません。

得たい証拠は、直近の実際の材料変更1件が、誰から誰へ、どの資料・表示へ伝わったかです。抽象的な負担感だけでなく、工程と未処理箇所を辿ります。詳細な質問候補は[負担調査](../literature/restaurant-burden-followup-20261014.md)にあります。

### 2. 原情報の入手・照合を確かめる

加工品・調味料の現品情報、規格書、仕入先回答が得られるか、現物と一致するかを確認する案です。入手できない情報をOCRや一般商品DBで埋めれば済むという仮定を置きません。API、保存・加工・再配布の許諾は、実際に候補となるサービス・データに限定して確認します。

材料単位の取得率、待ち日数、実作業時間、資料と現物の不一致を調べ、一般客向け公開情報と内部根拠を分けます。候補サービスの収録範囲・料金・権利・待ち時間は、[継続管理調査](../literature/information-operations-followup-20261014.md)の不明点を引き継ぎます。

### 3. 同じ品質水準で総負担を比較する

初期費用と継続費用を分け、資料取得、棚卸し、確認、入力、変更反映、差替え、教育、修正、問い合わせを測ります。待ち時間と実作業時間、営業時間内の中断も区別します。月額だけでなく端末・印刷・外注・仕入先側の作業を含める案です。

比較対象は現行の紙・表計算等です。何も情報提供していなかった店では導入後の作業が増える可能性があります。同じ情報品質を人手で実現する場合との削減と、現状からの時間削減を別に評価します。実際の価格選択等で支払意思を確認するまで、事業性を断定しません。

### 4. 公開前の模擬ケースと理解度で絞る

材料の代替、旧在庫併存、原本不鮮明、レシピ変更、担当者不在、紙の旧版を使う机上検証案です。注文管理を追加せずに、誤った否定表示、変更漏れ、確認不能の表示、追加操作時間を測れます。承認結果とは別の正解／未確定基準を用意します。

専門家・店舗・利用者が未確認、確認範囲、原材料としての不使用、工程の混入可能性をどう受け取るかを調べます。安全と誤解する率と、情報を探せない・何も分からず利用不能になる問題の両方を見ます。患者に未知の食品を食べてもらう検証は提案しません。

### 5. 実店舗の継続性・効果を評価する

前段の実行可能性を確認してから、実際の変更が起きる観察期間を設ける案です。未処理、放置、迂回、離脱と総工数を追い、確認完了率だけを成果にしません。導入直後の報告増加が検出改善なのか、実際の問題増加なのかも区別します。

短期間事故がなかったことだけで有効性を判断しません。情報不一致の低減と事故低減は別の結論です。現場・食品安全・法務・患者側の専門家レビューを要する論点を、ソフトの記録充足で代替しません。
