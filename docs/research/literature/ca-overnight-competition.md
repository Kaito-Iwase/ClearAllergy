# ClearAllergy 競争比較：店舗管理情報を来店前の横断検索へつなぐ価値
調査日時：2026-10-15 JST（2026-10-14 UTC）。公開一次資料の閲覧のみ。外部への連絡、サービス登録、データ変更はしていない。

## 結論
1. **「店舗のアレルゲン情報管理＋来店前の店舗横断メニュー検索」は、現時点でClearAllergy（CA）独自の価値とはいえない。** CAN EATは2023年にエリア横断メニュー検索のMAP β版を発表済み。三井不動産の&mogに掲載された実証報告は、管理サービスのデータをMAPで活用する構成まで明記している。[S5][S6]
2. **口コミ地図だけをCAN EATの消費者向け競合として扱うのは不十分。** 口コミ型の外食マップと、店舗協力によるメニューデータを条件検索するCAN EAT MAP β版は区別する。[S4][S5]
3. 差別化候補は「未対応の小規模店が、変更時にも維持できる工数で登録を続け、その情報から利用者が確認すべきことを把握して候補を探せる」こと。ただし**これは未検証仮説**。競合に該当機能がないという意味ではない。
4. &mogの実証報告は、登録の正確性と業務負荷低減に課題が残ったと記す。この過去の実証結果は、CAでもまず検証すべき障害を示す。現在も未解決とは断定しない。[S6]
5. 安全性、費用、更新時間、集客効果についてCA優位を示す比較データはない。CAN EATの現在価格も今回確定しない。古い料金を現在の価格として使わない。

## 2. 同じ具体例で比べる
以下のケース・CA仕様案・各方式の運用評価は調査者による比較設計であり、実際の店舗事故や実装済みCA仕様の記述ではない。紙・Excelも管理方法次第で高度化でき、「必ず誤る」「常に非効率」とは扱わない。

### ケースA：共通ソースを急に別製品へ置き換え、3メニューに影響
**条件**：開店前に仕入れ欠品が分かり、代替品を購入。包装の記載範囲は限定的。3メニューで使用予定。

- **CAN EAT**：既存の仕掛品連動機能が直接比較対象になる。食材や仕掛品の修正が影響メニューに反映される仕様は既発表。人が代替を把握し、資料を取得し、対象を登録する工程まで自動化されるとは読めない。[S2]
- **紙**：変更対象を一覧から探し、厨房・ホール・客向けの紙を差し替える設計が可能。複製数、共通原料の参照表、責任者が工数を左右する。紙の単一原本と口頭周知で済む店なら、新システムの入力の方が手間となる可能性もある。
- **Excel**：食材マスターと数式・参照関係があれば連動可能。フラットな表への手入力と、高度に構造化された既存Excelを同一視しない。Web公開用PDF等を別生成している場合は、その差替え工程を測る。
- **電話中心**：その場の担当者に確認できる利点がある一方、包装・厨房への照会、保留、再回答が必要になり得る。問い合わせ件数が少ない店では定常入力より合理的な場合もある。
- **専用サービス未導入**：情報管理自体がない場合と、既存の仕入れ・衛生管理で把握している場合を分ける。不明と答える運用にもコストと制約があるが、初期導入負担は発生しない。
- **CAで試す仮説**：代替品撮影→適用するメニュー確認→状態の公開までの総工数が、現行方法より小さいか。すべての工程を含め、他人による代行や未確認のままの短縮を隠さない。

**同じ測定**：変更を知った時刻、実食材切替時刻、入力実作業分、問い合わせ待ち分、公開までの分、影響対象の漏れ、未確認情報の誤った非使用表示、当日スタッフが答えを見つける時間。

### ケースB：旧ソースと新ソースの在庫が同じ日に残る
**条件**：ランチ前半は旧製品、後半は新製品になる予定だが切替時刻は未確定。仕込済み料理には旧製品が残る。

- **CAN EAT**：一部メニューだけ切替可能という公表はあるが、これはロット・提供単位・切替時刻の管理を保証する情報ではない。旧新併存の実運用仕様は未確認。[S2]
- **紙・Excel**：旧版・新版、容器ラベル、提供ロット表を併用できる。単に「最新版」に上書きすると現物とのずれが生じる可能性は、CAを含む全方式にある。
- **電話中心**：来店前に聞いた内容と当日の提供分が変わり得る。電話が無効なのではなく、確認対象の日時・料理・提供分を特定する必要がある。
- **未導入**：担当者の記憶と現物照合に依存する場合も、現物ロットを厳密管理している場合もある。専用ソフトの有無から管理品質を推定しない。
- **CAで試す仮説**：旧／新／未確定の適用状態を表せば、過剰な更新作業を増やさず説明の食い違いを減らせるか。別メニュー扱い、期間、ロット指定、確認待ち表示等を比較する。自動的に全件を新版へ切り替えることを成功条件にしない。

**同じ測定**：提供分と表示版の一致、切替前後の公開状態、仕込み残りの追跡、更新・ラベル貼付工数、担当交代後の判断一致率。これは情報運用の評価であり、安全性試験の代替ではない。

### ケースC：来店前に乳・卵について3店を比較、一部データが未確認
**条件**：A店は原材料確認済みだが共用設備の情報なし。B店はソースが未確認。C店は以前の口コミのみ。食べられることの保証を求める検索ではなく、候補と確認事項の把握を評価する。

- **CAN EAT**：QR公開に加え、エリア横断のメニュー条件検索を行うMAP β版という既存対照がある。口コミ地図だけを対照にして「CAだけがメニューから探せる」と結論しない。[S3][S5]
- **未知の扱い**：仕入先入力には資料の対象範囲の不明を扱う機能がある。ただし「各メニューの乳・卵が未知なら非使用検索から除外されるか」「利用者が未知と判別できるか」は今回確認できない。[S8]
- **紙・Excel公開**：各店がPDF・画像・Excelを公開していれば事前閲覧はできる。検索エンジン、店舗ホームページと組み合わせた手作業比較を現実的な代替に含める。
- **電話中心**：利用者は候補店へ順次確認できる。営業中の応答、回答者、未確認事項の再確認が制約になり得るが、個別相談の深さは単純なフィルタにない利点。
- **未導入**：第三者の口コミや常連としての知識、知っている店へ戻ること、外食を見送ることも実際の代替行動になり得る。CAの価値を既存アプリ間だけで測らない。
- **CAで試す仮説**：不明・未掲載・原材料非使用・調理時混入情報を混同せず、利用者が「何が分かり何を確認するか」を短時間で把握できるか。未知を隠して候補数を増やすことは成功ではない。候補ゼロも「地域に該当店なし」と「情報不足」を分ける。

**同じ測定**：候補と要確認点を挙げるまでの時間、資料を開いた数、電話した数、未知を非使用と誤解する割合、データ付き候補を見つけられる率、同じ条件で再利用する意向。仮想データ試験で差を検出した後、許可を得た実店舗調査で確かめる。

## 3. 差別化を否定・縮小する証拠
- CAN EATの現在のMAPまたは提供可能な別形式で、対象エリアの同じ店・メニューを同じ状態情報付きで探せる：発見体験の独自性は縮小する。
- CAN EATが現物切替・旧新併存・不明継承・公開承認を対象店に許容できる負担で扱う：更新運用上の独自性は縮小する。
- よく整理されたExcel＋公開PDF＋電話の方が、対象小規模店の総工数と利用者の理解で同等以上：専用サービスを追加する必然性が弱まる。
- CAで登録者が継続更新せず、検索可能データが不足する：UIが良くても横断発見の価値が成立しない。
- 閲覧はされるが新規候補発見や来店判断の改善がない、店舗も支払・継続を選ばない：集客対価や店舗課金の仮説が弱まる。
- 利用者が表示を食事の安全保証と受け取り、未知を読み分けられない：情報提供の設計を見直す必要がある。免責文を追加しただけで解決したと扱わない。

上記は反証条件であり、該当事実が今回発見されたという意味ではない。実測前に成功指標・許容工数・誤解の判定基準を決め、結果に応じて後付けで動かさない。

## 4. 次に得る証拠：優先順
1. **CAN EAT MAPの現行状態・対象と更新経路**：公開画面を別の許可された閲覧手段で確認。管理元、更新日、対象店、未知の表示、検索結果の説明を記録する。今回サービスURLはweb取得ツールで取得できなかったため、稼働も終了も断定できない。無断で管理画面へ登録したり店に連絡しない。
2. **同一ケースの仕様確認**：許可が得られた段階で、競合デモ／資料にケースA〜Cを当てる。「対応していますか」ではなく、操作順、状態遷移、公開範囲、待ち時間、例外時の回答を記録。未知から非使用へ誤変換されないかを確認する。
3. **対象小規模店の現状実測**：紙・Excel・電話・未導入を一括しない。固定／日替わり、加工品数、代替頻度、スタッフ数、問い合わせ頻度で層別。導入前、初回登録、最初の変更、継続更新を追う。初期の少数事例は探索であり市場代表値にしない。
4. **利用者タスク比較**：同じ地域・同じ店舗情報を使い、順序を入れ替えて比較する。情報量がCAだけ豊富な条件と、同じ情報を与えたUI比較を分け、データ供給効果と画面効果を混同しない。
5. **費用と継続性**：現在の同条件見積、資料請求・入力・確認・教育・差替え・対応の人手を含める。初回と月次を分離し、電話対応削減だけで投資回収を推計しない。掲載店と利用者の両方が一定地域にいる必要も検証する。

今すぐの開発示唆は、機能を増やして独自性を主張することではなく、同じ3ケースでどの工程が現行方法より改善するかを測れる状態にすること。連携・補完として成立する可能性もあるが、相手の接続可否や契約条件が不明なので提携前提にはしない。

## 調査限界
- デスク調査であり、ログイン後の操作、API同期、サービス利用者の実工数、現在の有料プランは確認していない。
- 公式MAPリンク https://can-eat.heliksdata.com/ はweb取得ツールで取得不能。アクセス失敗は事業終了やサービス停止の証拠ではない。
- 紙・Excel・電話は単一製品ではないため、運用設計と担当者に依存する。方式別優劣は実測前には仮説。
- 原材料の情報管理と、厨房での意図しない混入や個人の摂食判断を分離する。CA・CAN EAT・紙のどれにも安全優位を付与していない。
