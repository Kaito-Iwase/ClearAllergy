# ADR-001 — Keep current deployment and strengthen demonstrated boundaries

Status: **RECOMMENDED**（技術設計案）。2026-09-28。既存仕様・public wording・schema変更の承認ではない。

Context: R02/EX01のruntime semantic gap、R04のread/write境界、R07のfreshness未保証、R08のprovenance不足。一方pure policies/auth/storage/real DB harnessは既存。現行はprototype。

Decision: A1を推奨。transport/DBの全abstract化、DDD model、別backend、queue/event sourcingを先行導入しない。D01 semantic防御から始め、明示承認が必要なD03/05/06/10等を独立Issueへ分ける。

Rejected alternatives: A0ではknown gap残存、A2は全feature移行費用に見合うvariation証拠なし、A3は独立scale/deploy要求なし。Simpler alternative: D01/D02を現行ファイルへ最小修正し、use case file抽出も後で判断。

Consequences: Prisma/Next couplingはserverに残る。DB constraints/real provider/cacheのintegration testを省けない。食品根拠・UX・運用責任はarchitectureだけで解決しない。

Validation: [verification plan](../../implementation/verification-plan.md)、[adversarial review](../adversarial-review.md)。Decision再開条件: 既存境界でcritical testsを書けない実証、独立scale/team/provider追加、transaction構造の拡大。単なる行数増大は再開根拠にしない。
