# 保存後の公開確認 — 2026-10-23

[操作仕様](../guide/product.md#menus) · [公開条件](../guide/rules.md#publication) · [変更対応表](../guide/change-map.md) · [検証入口](../guide/verification.md)

## 対象と理由

基準mainは `58f149d32d71ce3068995541e34aae1ed938bc52`。食品変更を非公開保存し、保存済み最新版へ別に公開する条件を維持したまま、保存後に画面を移動して公開する負担を減らします。利用者の承認に基づき同じページの確認欄へ変更し、補助ボタン名は「保存」、説明は「公開せずに保存します」とします。確認品質や食品安全性の向上が実証されたという変更ではありません。

新規・編集で実際に非公開保存された場合だけ、保存済み名前、CONTAINS、MAY_CONTAIN、注意書き全文、展開可能なその他の登録内容を表示します。価格・画像構図などで公開を維持した保存へ、非公開と誤表示しません。写真の差替えは既存の食品変更判定に従います。

## 保持する条件

- 確認欄は編集中の値や過去の食品確認履歴で代用せず、既存の所有者用GETを検証して使います。編集保存ではID・保存版・食品版が保存成功応答と一致することを要求します。15秒で読取を中止し、読取再試行と再保存を区別します。
- 表示中は入力を無効化し、別公開PUTへその保存版を送ります。保存後・確認後の同時編集は既存の409で拒否します。自動的に新しい版へ付け替えません。
- 「保存」・閉じる・Escapeは確認終了だけで、追加保存や公開を送りません。公開失敗時は保存済み内容を保持し、公開要求のみ再試行できます。409は確認をやり直す必要があります。
- UNKNOWNは非公開で保存可能ですが、名前と件数を示して公開ボタンを出しません。該当入力へ移動し、修正後に再保存します。FREEやMAY_CONTAINへ自動変更しません。未解決事項は既存の明示解除経路を保持します。
- 新規作成IDを受け取った後のGET失敗は、同じIDの読取再試行です。POSTを複製せず、同じページで編集を続ける場合はPUTを使います。
- 所有者・Origin・公開適格性・食品版・公開確認版・未解決・公開readのサーバー制約、公開停止、キャッシュ方針を維持します。DB migration・APIレスポンス契約・認証設定・依存バージョンは変更しません。

## 検証の限界

新規ブラウザ回帰のAPIはすべて架空応答です。実サーバーの認可・UNKNOWN/欠損・未解決・競合はAPI単体テスト、実DB制約はCIの使い捨てPostgreSQLの既存回帰と区別します。ユーザーの既存Brave、認証セッション、本番のデモ商品や写真には操作を行いません。本番への保存・公開操作を試験していないため、配備確認が成功しても実認証を伴う本番編集の完了とは表現しません。
