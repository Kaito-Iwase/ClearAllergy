# バグ管理ルールの叩き台

## 目的

ClearAllergy のバグ報告、優先度判断、暫定対応、恒久対応、修正確認を同じ形式で扱うための叩き台です。

## バグ分類

| 分類 | 説明 | 例 |
| --- | --- | --- |
| 認証・認可 | ログイン、Clerk、shopId 所有権、他店舗アクセス | 他店舗メニューが編集できる |
| 公開条件 | `isPublished`、`UNKNOWN`、公開店舗条件 | `UNKNOWN` のまま公開できる |
| アレルゲン表示 | 状態ラベル、28品目欠損、個人警告 | `MAY_CONTAIN` が表示されない |
| 入力・バリデーション | 必須、数値、画像 URL、JSON | 価格に小数が保存される |
| 管理 UI | 店舗情報、メニュー作成、メニュー編集、一覧 | 保存エラーが見えない |
| 公開 UI | 店舗一覧、店舗詳細、メニュー詳細 | スマホで表が崩れる |
| 画像 | Vercel Blob、URL 検証、表示調整 | 外部 URL が公開 API に出る |
| データ整合性 | Prisma relation、欠損リンク、seed/repair | 28品目リンクが欠ける |
| パフォーマンス | 遅いクエリ、N+1、画像過大 | 店舗詳細が遅い |
| 文言 | 必須/推奨の説明、エラー文、表現の揺れ | 原材料名が必須と誤読される |

## 重大度

| 重大度 | 基準 | 例 |
| --- | --- | --- |
| S0 | 安全性・認可・データ漏洩に直結し、即時対応が必要 | 他店舗データを閲覧/更新できる |
| S1 | 公開情報の誤表示、公開条件破壊、主要導線停止 | `UNKNOWN` のまま公開できる、公開メニューが見えない |
| S2 | 主要機能の一部が使いにくい、回避策あり | 画像アップロード失敗時の再試行が分かりにくい |
| S3 | 表示崩れ、軽微な文言、限定条件の不具合 | ラベルの表現揺れ |

## 優先度

| 優先度 | 基準 |
| --- | --- |
| P0 | 今日中に着手。公開事故、認可、データ破壊 |
| P1 | 次の作業単位で対応。主要導線や公開条件 |
| P2 | 近日対応。UX 改善、再現頻度が中程度 |
| P3 | バックログ。軽微、低頻度、影響が限定的 |

重大度は影響の大きさ、優先度は着手順です。S1 でも影響範囲が限定的なら P1/P2、S3 でも問い合わせが多ければ P2 に上げます。

## 再現手順の書き方

| 項目 | 書く内容 |
| --- | --- |
| 前提データ | 店舗、メニュー、公開状態、アレルゲン状態 |
| ログイン状態 | 未ログイン、店舗管理者、他店舗管理者 |
| URL | 実際に開いたルート |
| 操作 | クリック、入力、保存、戻る、再読み込み |
| 結果 | 画面表示、API ステータス、DB 変化 |

## 期待結果 / 実際結果

| 種類 | 書き方 |
| --- | --- |
| 期待結果 | 現行仕様または確認済み文書に基づくべき状態 |
| 実際結果 | 観測した状態。推測を混ぜない |
| 未確定 | 仕様が文書化されていない場合は「未確定」と書く |

## 影響範囲

| 観点 | 確認項目 |
| --- | --- |
| 公開画面 | 未ログイン利用者に見えるか |
| 管理画面 | 店舗管理者の作業が止まるか |
| API | 直打ちで再現するか |
| DB | データ破損、欠損、誤公開があるか |
| 認可 | 他店舗に影響するか |
| アレルゲン | `UNKNOWN` / `CONTAINS` / `FREE` / `MAY_CONTAIN` の意味が崩れるか |
| スマホ | 操作不能や表示崩れがあるか |

## 暫定対応

| 状況 | 暫定対応例 |
| --- | --- |
| 誤公開リスク | 該当メニューを非公開に戻す |
| アレルゲン欠損 | `UNKNOWN` 補完と公開解除を実施する |
| UI 表示崩れ | 操作可能な代替導線を案内する |
| 画像 URL 不正 | 画像を非表示または許可済み URL に差し替える |

暫定対応は恒久対応の代わりにしない。必ず恒久対応欄を残す。

## 恒久対応

| 種類 | 対応例 |
| --- | --- |
| バリデーション追加 | API 側に最終チェックを追加 |
| UI 改善 | エラー位置、ボタン状態、文言を修正 |
| データ補修 | repair script または migration を検討 |
| テスト追加 | 公開条件、認可、E2E 観点を追加 |
| 文書更新 | 仕様が曖昧だった場合に docs を更新 |

## 修正確認方法

| 修正内容 | 確認方法 |
| --- | --- |
| 公開条件 | `UNKNOWN` 残りで公開できないこと、全確定で公開できること |
| 認可 | 他店舗 ID で取得/更新/削除できないこと |
| 入力 | 未入力、不正数値、不正画像 URL を試す |
| UI | PC とスマホ幅で確認 |
| 公開画面 | 店舗一覧、店舗詳細、メニュー詳細を確認 |
| データ | 必要なら Prisma Studio / DB クエリ / API レスポンスで確認 |

## バグ修正時の注意

- 認証・認可・所有権確認を緩めない。
- 公開条件を UI だけで直さない。
- `UNKNOWN` を隠して解決したことにしない。
- DB スキーマ変更は別タスクとして明示する。
- 文言だけの問題でも、現行コードと矛盾しないか確認する。
