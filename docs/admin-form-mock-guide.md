# 管理画面主要フォームのモック整理

## 目的

今後の UI 改善で、管理画面フォームの入力順、重要度、エラー表示を揃えるための叩き台です。

この文書は Figma ではなく Markdown ベースのモック整理です。現行実装から確認できたことと、改善提案を分けています。

## 店舗情報フォーム

### 目的

公開店舗ページと店舗一覧カードに表示される店舗基本情報を更新する。

### 入力項目一覧

| 順 | 項目 | 現行の必須 / 推奨 / 任意 | 保存ルール |
| --- | --- | --- | --- |
| 1 | 店舗名 | 必須 | 空白だけは保存不可 |
| 2 | お店の説明 | 任意 | 空なら `null` |
| 3 | 平均予算（円） | 任意 | 空可。入力時は 0 以上の整数 |
| 4 | 店舗画像ファイル | 任意 | 保存時にアップロード |
| 5 | 現在の画像URL | 任意 | 許可された保存済み画像 URL のみ |
| 6 | 住所 | 任意 | 空なら `null` |
| 7 | 営業時間 | 任意 | 一括入力または平日 / 土日祝から文字列化 |
| 8 | 定休日 | 任意 | 空なら `null` |
| 9 | 電話番号 | 任意 | 空なら `null` |
| 10 | 備考 | 任意 | 空なら `null` |
| 11 | 店舗画像の表示調整 | 任意 | frame / fit / position / zoom を保存 |

### 入力順

現行フォームは、店舗名、説明、平均予算、画像、住所、営業時間、定休日、電話番号、備考の順です。

推奨する入力順:

1. 店舗名
2. お店の説明
3. 住所
4. 営業時間
5. 定休日
6. 電話番号
7. 平均予算
8. 備考
9. 店舗画像
10. 画像表示調整

### スマホでの優先表示

| 優先 | 表示内容 |
| --- | --- |
| 高 | 保存ボタン、エラー、店舗名 |
| 高 | 公開プレビューの要点 |
| 中 | 住所、営業時間、定休日、電話番号 |
| 中 | 平均予算、備考 |
| 低 | 画像 URL の手動入力、画像表示調整 |

### PCでの表示方針

- 左側にフォーム、右側に公開プレビューと QR カードを置く構成が現行に近い。
- 入力ヒントは補助カラムに寄せ、フォーム本体の縦スクロールを長くしすぎない。
- 画像調整は画像がある時だけ表示する現行方針を維持する。

### エラー表示方針

| エラー | 現行表示 | 方針 |
| --- | --- | --- |
| 店舗名未入力 | 「店舗名は必須です。」 | フォーム上部と店舗名直下の両方を検討 |
| 平均予算不正 | API のエラーメッセージ | 平均予算欄直下に出すとよい |
| 画像 URL 不正 | API のエラーメッセージ | 画像欄またはフォーム上部に表示 |
| 保存成功 | 「店舗情報を保存しました。」 | 上部に出す現行を維持 |

### 現状の問題点

- 店舗情報フォーム内で「公開される情報」と「管理用の操作」が混在している。
- 画像 URL の手動入力は通常操作ではないが、他項目と同じ重さで表示されている。
- 営業時間は UI 上は分割入力できるが、DB には `hours` の単一文字列で保存される。

### 改善提案

- 「公開ページに表示される情報」セクションと「画像・表示調整」セクションに分ける。
- 画像 URL 手動入力は詳細設定に畳む。
- 営業時間の保存形式は DB 変更なしで、現行の文字列保存を前提にする。

## 営業時間フォーム

### 目的

店舗の営業時間を、公開ページで読みやすい文字列として登録する。

### 入力項目一覧

| 項目 | 現行の必須 / 推奨 / 任意 | 保存ルール |
| --- | --- | --- |
| 設定方法 | 任意 | `single` または `weekdayHoliday` の UI state |
| 一括入力 | 任意 | `hours` にそのまま保存 |
| 平日 | 任意 | `平日 {入力値}` として保存 |
| 土日祝 | 任意 | `土日祝 {入力値}` として保存 |

### 入力順

1. 設定方法
2. 一括入力または平日 / 土日祝
3. 定休日
4. 補足が必要なら備考

### スマホでの優先表示

- 設定方法ボタンは縦並びでも読める幅を保つ。
- 平日 / 土日祝はスマホでは縦並びにする。
- 保存後に実際に公開される文字列を小さくプレビュー表示する。

### PCでの表示方針

- 設定方法は横並びのセグメント。
- 平日 / 土日祝は 2 カラム。
- 定休日は営業時間の直後に置く。

### エラー表示方針

現行では営業時間そのものの形式エラーは確認していません。入力形式を厳密化する場合は、DB スキーマ変更ではなく UI 側の補助文言と任意チェックから始める。

### 現状の問題点

- `parseBusinessHoursText` は「平日」「土日祝」「土日」「休日」の文字列から推定しており、自由入力との境界が曖昧。
- 保存形式は単一文字列のため、今後の詳細な営業時間 UI とは完全には一致しない。

### 改善提案

- 当面は `hours` 文字列保存を維持する。
- UI 文言で「営業時間が不規則な場合は一括入力を使う」と明示する。
- 営業時間の構造化は別タスクとして扱う。

## メニュー作成フォーム

### 目的

新しいメニューを作成し、必要なら作成時点で公開状態にする。

### 入力項目一覧

| 順 | 項目 | 現行の必須 / 推奨 / 任意 | 保存ルール |
| --- | --- | --- | --- |
| 1 | メニュー名 | UI では必須。API は未指定時に「新しいメニュー」を補完 | 公開時は必須 |
| 2 | 価格（税込・円） | 任意 | 空可。入力時は 0 以上の整数 |
| 3 | 説明 | 任意 | 空なら `null` |
| 4 | カテゴリ | 任意 | 空なら `null` |
| 5 | 原材料名 | 推奨 | 空でも保存・公開可 |
| 6 | 注意書き | 推奨 | 空でも保存・公開可 |
| 7 | 食品画像ファイル | 任意 | 作成時にアップロード可能 |
| 8 | 画像URL | 任意 | 許可された保存済み画像 URL のみ |
| 9 | 画像表示調整 | 任意 | 画像がある時に設定 |
| 10 | 公開状態 | 任意 | `isPublished` |
| 11 | アレルゲン28品目 | 公開時必須 | 初期値は全件 `UNKNOWN` |

### 入力順

現行は「基本情報」内に公開ボタンと登録ボタンがあり、アレルゲン28品目は下部です。

推奨する入力順:

1. メニュー名
2. アレルゲン28品目
3. 原材料名
4. 注意書き
5. 価格
6. 説明
7. カテゴリ
8. 画像
9. 公開状態
10. 登録

### スマホでの優先表示

- 公開に必要な「メニュー名」と「アレルゲン28品目」を上に置く。
- 原材料名・注意書きは推奨として、アレルゲン設定の近くに置く。
- 画像調整は後半に置く。

### PCでの表示方針

- 左側に基本情報、右側または下部にアレルゲン28品目。
- アレルゲン28品目は 2 カラムを維持。
- 公開状態は保存ボタンの近くに置き、公開失敗の理由を同じ領域に表示する。

### エラー表示方針

| エラー | 現行表示 | 方針 |
| --- | --- | --- |
| メニュー名未入力 | 「名前は必須です。」 | ラベルを「メニュー名」と揃え、「メニュー名は必須です。」に統一候補 |
| 価格不正 | API の価格エラー | 価格欄直下へ表示候補 |
| 公開条件不足 | API の公開エラー | 公開状態ボタン付近に表示候補 |
| 画像アップロード失敗 | 共通エラー | 画像欄付近に表示候補 |

### 現状の問題点

- 作成 UI はメニュー名を必須扱いするが、API は空 body で下書きを作れる。
- 原材料名ラベルに絵文字が含まれる。画面全体の文言統一ルールでは扱いを決める必要がある。
- 公開状態を先に切り替えられるが、アレルゲン未設定のまま登録すると API で失敗する。

### 改善提案

- 作成フォームでは「公開する」ボタンを押す前に未設定数を表示する。
- `UNKNOWN` が残っている場合は公開トグルの近くに理由を表示する。
- 原材料名・注意書きの推奨文言は現行のまま維持する。

## アレルゲン編集フォーム

### 目的

メニューごとにアレルゲン28品目の状態を確定し、公開条件を満たせるようにする。

### 入力項目一覧

| 状態 | 管理画面ラベル | 意味 |
| --- | --- | --- |
| `UNKNOWN` | 未設定 | まだ確定していない |
| `CONTAINS` | 含む | メニューに含まれる |
| `FREE` | 含まない | メニューに含まない |
| `MAY_CONTAIN` | 含む可能性があります | コンタミネーション等の可能性あり |

### 入力順

1. アレルゲン名を確認
2. 現在の状態を確認
3. 4 状態から選択
4. 未設定数を確認
5. 保存または公開

### スマホでの優先表示

- 1品目ごとにカード表示。
- 4状態ボタンは折り返し前提。
- 未設定数のサマリーを上部に固定または近接配置する。

### PCでの表示方針

- 2 カラム表示を基本にする。
- 状態ボタンの並びは「未設定 / 含む / 含まない / 含む可能性があります」を維持する。
- 大量入力向けの一括操作は現行未確認のため、追加する場合は別タスクにする。

### エラー表示方針

| エラー | 方針 |
| --- | --- |
| 未設定が残って公開不可 | 未設定品目名を表示 |
| 不明な slug | API エラーとして表示 |
| 不正な status | API エラーとして表示 |

### 現状の問題点

- 公開不可条件の中心だが、フォーム上部に未設定数の常時サマリーは確認していない。
- 28品目すべての入力が必要なため、スマホでは縦に長い。

### 改善提案

- 未設定数と未設定品目の先頭数件を上部に表示する。
- `UNKNOWN` を選ぶ操作は残す。未確認情報を無理に `FREE` にさせないため。
- 公開ボタンを押す前に、未設定がある場合は「下書き保存のみ可能」と明示する。
