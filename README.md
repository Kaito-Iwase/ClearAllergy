# ClearAllergy

外食時にアレルゲン情報を確認しづらいという課題に対して、  
**店舗が情報を更新できること** と  
**利用者がスマートフォンから見やすく確認できること**  
の両方を目指して開発している Web アプリです。

## 背景

食物アレルギーを持つ人にとって、外食時の情報確認は大きな負担になりやすいです。  
店舗によってはアレルゲン情報の提示方法が統一されておらず、来店者が毎回スタッフに確認しなければならないこともあります。

この課題に対して、ClearAllergy では次の2点を重視しています。

- **店舗側が自分で情報を登録・更新できること**
- **利用者側がスマホで素早く確認できること**

## 目指していること

「聞かなくても分かる」外食体験を増やすことです。

店舗側が管理画面からメニューとアレルゲン情報を更新し、  
利用者側は公開ページから各メニューのアレルゲン情報を確認できます。  
また、利用者ごとの気になるアレルゲン設定をもとに、注意が必要なメニューを見つけやすくする設計にしています。

## 設計で意識したこと

### 1. 管理側と公開側を分ける

利用者に見せる画面と、店舗が編集する画面は責務が違うため、ルーティングと API の責務を分けています。  
これにより、公開側は閲覧中心、管理側は認証済み店舗のみ更新可能という形に整理しています。

### 2. アレルゲン情報をマスタ管理する

アレルゲン28品目を固定のベタ書きではなく、DB のマスタとして管理しています。  
表示順も `sortOrder` で制御することで、公開側と管理側で同じ基準を使えるようにしています。

### 3. メニュー作成導線を edit 画面に寄せる

新規作成専用ページを増やすのではなく、  
**先に空の下書きを作成して、そのまま edit 画面へ遷移する**  
形にしています。  
これにより、作成と編集の UI を分けずに済み、管理画面の複雑さを減らしています。

### 4. 利用者側はログイン不要でも使えるようにする

一般利用者のアレルゲン設定は localStorage で保持しています。  
ログインを必須にしないことで、店頭で QR から開いた人でもすぐ使えることを優先しました。

### 5. 店頭利用を意識した導線を作る

店舗公開URLをそのまま共有するだけでなく、QRコードでも開けるようにしています。  
店頭POPやメニュー表に載せることを想定しています。
