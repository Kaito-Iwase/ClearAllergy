## 1. 今日やったこと（作業ログ：時系列）

### 1) APIの役割を分離した（公開用 / 管理用）
- 公開（ユーザーが見る）  
  - `GET /api/menus/:menuId`：メニュー詳細（アレルゲン状態込み）
- 管理（店舗が更新する）  
  - `PUT /api/admin/menus/:menuId`：メニュー更新（アレルゲン状態更新含む）

**学び**
- 「更新（PUT）」は誰でも叩けると危険なので、`/api/admin/...` に寄せる設計が安全。
- 実際に、`PUT /api/menus/:id` を叩いて 405 が出たとき、原因は「PUTが無い」だけでなく「そもそもPUTは `/api/admin/...` に置いていた」＝URL違いだった。

---

### 2) 405 Method Not Allowed の正体を理解した
実行したコマンド例：
```bat
curl -i -X PUT "http://localhost:3000/api/menus/cmm8p0mz6000bwnloulxvpm7x" ^
  -H "Content-Type: application/json" ^
  -d "{"shopId":"cmm8ollib0001wnqcyimmbm6a","allergenStatusBySlug":{"egg":"FREE","milk":"CONTAINS"}}"
```

返ったもの：
- `HTTP/1.1 405 Method Not Allowed`

**意味（超重要）**
- 405 = 「そのURLは存在するが、そのHTTPメソッド（PUT）は実装されていない」

今回の原因は2段階あった：
1. `/api/menus/:id` 側には PUT を用意していない（公開用GETだけの想定）
2. PUTは `/api/admin/menus/:id` に実装していた（叩くURLが違っていた）

---

### 3) 正しいURLにPUTしたら200で更新できた
正しい更新先（管理用）：
```bat
curl -i -X PUT "http://localhost:3000/api/admin/menus/cmm8p0mz6000bwnloulxvpm7x" ^
  -H "Content-Type: application/json" ^
  -d "{"shopId":"cmm8ollib0001wnqcyimmbm6a","allergenStatusBySlug":{"egg":"FREE","milk":"CONTAINS"}}"
```

返ったもの：
- `HTTP/1.1 200 OK`
- JSONが返ってきた

**注意**
- `updatedAt` が必ず変わるとは限らない（MenuItem自体を更新してない場合など）。
- 本当に更新されたかは「公開GETで確認」が確実。


期待する変化：

これで「管理PUT → 公開GET」で反映確認できた。

### 5) 管理画面の編集ページ（URL設計B）を作った
採用した構成：**B（editページを分ける）**
- `app/(admin)/.../menus/[menuId]/edit/page.tsx`

**ハマりポイント**
- `(admin)` は Route Group（URLに出ない）  
- でも `admin` は通常フォルダ（URLに出る）  
- フォルダが `app/(admin)/admin/...` になっていたため、URLは `/admin/...` になった

つまり：
- ページが `app/(admin)/admin/menus/[menuId]/edit/page.tsx` にある場合
  - URLは `http://localhost:3000/admin/menus/<menuId>/edit`

### 6) `useState` エラーを解決した（Server/Clientの分離）
出たエラーの要点：
- **useState は Client Component でしか使えない**
- `"use client"` は **ファイル先頭に置く必要がある**（関数の中に書いても無効）

**解決策（王道）**
- `page.tsx`（Server Component）：初期データ取得だけ担当
- `AdminMenuEditClient.tsx`（Client Component）：クリック・入力・保存を担当（先頭に `"use client"`）

#### 最終的なファイル構成（この形が正解）
- `app/(admin)/admin/menus/[menuId]/edit/page.tsx`  
  - サーバで `GET /api/allergens` と `GET /api/menus/:id` を叩く  
  - `initialStatusBySlug` を作って Client に渡す
- `app/(admin)/admin/menus/[menuId]/edit/AdminMenuEditClient.tsx`  
  - `"use client"` を先頭に書く  
  - `useState` で三択の状態を管理  
  - 保存ボタンで `PUT /api/admin/menus/:id` を叩く

## 2. 学習メモ（小さいことから）

### 2.1 405 Method Not Allowed とは？
- HTTPステータスコードの一種
- 意味：**そのURLはあるが、そのメソッド（PUT/POSTなど）が許可されていない**

今回の読み替え：
- 「URLが間違い」か「そのURLにPUTが未実装」

---

### 2.2 `/api/menus` と `/api/admin/menus` の違い
- `/api/menus`：公開向け（閲覧用）
- `/api/admin/menus`：管理向け（更新用）

**なぜ分ける？**
- 更新APIは誰でも叩けると危険（将来は認証が必須）
- 公開向けはGET中心でOK

---

### 2.3 `()` と `[]` の違い（Next.jsのフォルダ記法）
- `[]`：動的ルート（URLに値が入る）
  - 例：`[menuId]` → `/.../<menuId>`
- `()`：Route Group（URLに出ない整理用フォルダ）
  - 例：`(admin)` → URLには出ない

**注意**
- `(admin)` の下に普通の `admin` フォルダを作ると、URLに `/admin` が出る。

---

### 2.4 `"use client"` のルール
- `"use client"` は **ファイル先頭**に書く必要がある
- 関数の中に書いても無効

**なぜ？**
- Next.jsが「このファイルはクライアント側で動く」と判定するのはファイル単位だから

---

### 2.5 Server Component / Client Component の役割分担（今回の型）
- Server（page.tsx）
  - DB/APIから初期データ取得
  - 初期値を計算（例：28品目FREE→既存状態で上書き）
- Client（AdminMenuEditClient.tsx）
  - クリック、入力（useState）
  - 保存（fetch PUT）
