### 2) `app/api` 配下で「route.ts と page.tsx を同じパスに置く」衝突を解消した

発生したエラー（要点）：

- `/api/menus/[menuId]` に `route.ts` と `page.tsx` が両方存在して衝突

意味：

- Next.jsでは同じURLパスで「API（route.ts）」と「ページ（page.tsx）」は共存できない

対応：

- `app/api/menus/[menuId]/page.tsx` を削除し、APIは `route.ts` のみにした

---

### 3) ユーザー側の商品詳細ページを作成（Prisma直叩き）

作成したページ（例）：

- `app/(public)/shops/[shopId]/menus/[menuId]/page.tsx`

狙い：

- `fetch("http://localhost:3000/...")` のような **localhost固定問題**を避ける
- サーバーコンポーネント上で **Prismaで直接DBを読む**ことで、本番でも壊れにくい形にする

---

### 4) 404 の原因を切り分けて修正（URLとフォルダ構造の一致）

学び：

- Next.js App Router は「フォルダ構造＝URL構造」
- `shops` がフォルダ階層に無ければ `/shops/...` は404になる

対応：

- `/shops/...` を使うために、ページを `shops/[shopId]/menus/[menuId]` の階層に揃える考え方を整理

---

### 5) PrismaClientValidationError の原因を特定して修正（menuIdがundefined）

発生したエラー（要点）：

- `findUnique(where: { id: undefined })` になって落ちる
- つまり `menuId` が `undefined` になっていた

原因：

- Next.js 16.1.6（Turbopack）環境で、ページに渡される `params` が Promise 扱いになるケースがあり、
  そのまま `params.menuId` にアクセスすると値が取れないことがある

対応（解決策）：

- `params` を `await` してから取り出すように変更

```ts
type PageProps = {
    params:
        | Promise<{ shopId: string; menuId: string }>
        | { shopId: string; menuId: string };
};

export default async function MenuDetailPage({ params }: PageProps) {
    const { shopId, menuId } = await params; // ←ここが重要
}
```

結果：

- `menuId` が取得できるようになり、Prismaの `findUnique` が正常に動作
- 商品詳細ページが表示でき、警告バナーも出せる状態になった

## 2. 学習メモ：記法・概念まとめ（小さいことから）

### 2.1 `[]`（角括弧）— 動的ルート（URLの変わる部分）

例：

- `app/shops/[shopId]/menus/[menuId]/page.tsx`

URL：

- `/shops/<shopId>/menus/<menuId>`

意味：

- `[shopId]` は「ここに実際の値が入る」変数の場所
- ページ側では `params.shopId` として受け取る

---

### 2.2 `()`（丸括弧）— Route Group（URLに出ない整理フォルダ）

例：

- `app/(public)/shops/page.tsx`

URL：

- `/shops`（`(public)` はURLに出ない）

意味：

- URLを変えずにフォルダを分けられる（public/adminの分離などに便利）

---

### 2.3 `{}`（波括弧）— JavaScript/TypeScriptの記法（フォルダ記法ではない）

よく出るパターン：

- オブジェクト：`const x = { a: 1 }`
- 分割代入：`const { a } = x`
- JSXで式を書く：`<p>{menu.name}</p>`

---

### 2.4 `notFound()` — Next.jsの404を返す関数

- `notFound()` を呼ぶと「ページが存在しない」扱いになり 404 になる
- 今回は「menuが取れない」「非公開」のときに `notFound()` する設計

---

### 2.5 PrismaClientValidationError とは？

- Prismaが「引数の形が間違っている」と判断したときに出るエラー
- 今回は `findUnique(where: { id: undefined })` が原因
    - `findUnique` は主キー（id）で1件取るので、idが無いと成立しない
